# OmniQR 后续功能与版本计划

## 1. 规划原则

- 本地优先：核心功能不依赖账号、服务器或网络。
- 快速完成：生成、扫码、复制、保存这几条链路要少步骤。
- 记录可复用：用户生成或扫过的内容，应能被再次打开、复制、分享和重新生成。
- 安全克制：对链接、WiFi 密码、联系人信息等敏感内容给出明确边界，不做隐性上传。
- 跨端可落地：优先保证 Android App 和 H5，后续再评估微信小程序。

## 2. 版本路线

### V0.1 项目骨架与首页

目标：把默认 uni-app 模板改成 OmniQR 的真实应用入口。

范围：

- 首页工具箱布局
- 页面路由结构
- 全局视觉风格
- 基础导航和空状态
- 本地记录数据结构封装

验收：

- 打开 App 看到 OmniQR 工具箱，而不是默认模板。
- 首页可以进入二维码生成、WiFi、名片、记录四个入口。
- 本地记录模块有统一读写接口。

当前进度：

- 已完成首页工具箱界面，并优化工具卡、最近记录和底部导航。
- 已新增生成、WiFi、名片、记录、详情页面。
- 已接入首页卡片、扫码按钮、最近记录和底部 Tab 的页面跳转。
- 已封装本地记录模块，支持列表、新增、详情、收藏、删除。

### V0.2 基础二维码生成

目标：完成普通文本和链接二维码生成闭环。

范围：

- 文本二维码
- 链接二维码
- 二维码预览
- 复制内容
- 生成后自动保存记录
- 删除记录

验收：

- 输入文本可以生成二维码。
- 输入链接可以生成二维码。
- 生成后的内容可以保存到本地记录。
- 记录页可以重新打开并再次生成二维码。

当前进度：

- 已接入 `qrcode-generator`，普通文本/链接二维码可本地生成。
- 生成页已改为点击“生成”后才显示二维码。
- 已完成二维码预览组件 `QrPreview.vue`，支持 OmniQR 深青外框和角落水印。
- 已新增 `qrExport.ts`，可导出带品牌外框和水印的二维码图片；App 端相册保存仍需真机验证。
- 记录页点击可进入详情页，详情页支持复制、收藏、删除和重新生成。

剩余：

- H5 保存图片能力按平台降级，仍需完善下载体验。
- 需要在 Android 基座验证 `saveImageToPhotosAlbum` 权限和保存结果。

### V0.3 WiFi 与名片二维码

目标：覆盖两个高频场景。

范围：

- WiFi 表单
- WiFi 标准格式生成
- vCard 名片表单
- vCard 内容生成
- 表单校验和错误提示

验收：

- WiFi 二维码可被另一台设备识别为 WiFi 信息。
- 名片二维码可被手机联系人应用识别为联系人信息。
- 空字段不会生成无效格式。

当前进度：

- WiFi 页面已接入真实二维码预览、复制、自动保存记录和保存二维码图片。
- WiFi 支持 WPA/WPA2、WEP、无密码、隐藏网络和格式转义。
- 名片页面已接入真实 vCard 二维码预览、复制、自动保存记录和保存二维码图片。
- 名片支持姓名、手机、公司、职位、邮箱、网址、地址、备注和记录备注名称。

剩余：

- 需要在真机上用另一台设备验证 WiFi 识别和联系人导入兼容性。
- 详情页仍可继续按 WiFi、名片做结构化字段展示。

### V0.4 扫码与相册识别

目标：补齐读取二维码的能力。

范围：

- 相机扫码
- 扫码结果页
- 链接识别和打开确认
- 从相册选择图片识别
- 保存扫码记录

验收：

- Android 真机可调用相机扫码。
- 识别链接时先展示结果，再由用户确认打开。
- 扫码结果可进入历史记录。

当前进度：

- 首页扫码入口已调用 `uni.scanCode`。
- 扫码成功后会保存本地记录并进入记录详情页。
- H5 端扫码能力仍按平台降级。

剩余：

- Android 真机相机权限和扫码结果仍需验证。
- 链接安全提示、打开确认和从相册识别二维码仍待实现。

### V0.5 记录管理增强

目标：让工具箱真正可长期使用。

范围：

- 搜索
- 类型筛选
- 收藏
- 标签
- 批量清理
- 最近使用排序
- JSON 导入导出

验收：

- 用户可快速找到历史二维码。
- 清空记录不会删除收藏内容。
- 导出的 JSON 可再次导入并去重。

当前进度：

- 记录页已支持搜索、类型筛选和收藏切换。
- 设置页已支持导出记录 JSON 到剪贴板。
- 设置页已支持清空非收藏记录和清空全部记录。

剩余：

- JSON 导入、去重、标签和最近使用排序仍待实现。

## 3. 后续功能池

### 3.1 二维码类型扩展

- 邮箱二维码：生成 `mailto:` 链接。
- 电话二维码：生成 `tel:` 链接。
- 短信二维码：生成 `sms:` 链接。
- 地图位置二维码：保存经纬度或地图链接。
- 日历事件二维码：生成活动时间、地点和备注。
- 支付二维码归档：只保存图片和备注，不主动解析支付内容。

优先级建议：

- 高：邮箱、电话、短信。
- 中：地图位置、日历事件。
- 低：支付二维码归档。

### 3.2 二维码美化

- 品牌外框和角落 `OmniQR` 水印（已完成基础版）
- 前景色和背景色
- 二维码尺寸
- 边距
- 圆角风格
- 中心 Logo
- 明暗模式预览
- 导出 PNG

注意事项：

- 美化不能牺牲可识别率。
- Logo 嵌入必须限制大小。
- 背景透明导出可作为后续增强，不进 MVP。

### 3.3 扫码体验增强

- 连续扫码
- 扫码成功震动
- 扫码成功音效开关
- 手电筒开关
- 识别剪贴板中的二维码链接
- 对危险链接给出二次确认

### 3.4 记录和数据增强

- 收藏夹
- 标签
- 备注
- 最近使用
- 重复内容合并
- 导入导出
- 数据迁移版本号
- 本地加密存储敏感字段

### 3.5 模板和批量能力

- 常用模板：门店 WiFi、个人名片、活动链接、客服联系方式
- 批量生成：从文本列表或 CSV 批量生成
- 批量导出：压缩包或相册批量保存
- 打印排版：A4 多二维码排版

该部分适合在 V1.0 后再做，避免首版复杂度过高。

## 4. 信息架构建议

首版采用底部 Tab 或首页工具箱二选一。

建议先用首页工具箱：

- 首页：四个核心入口和最近记录
- 生成：按类型展示表单和预览
- 记录：历史、收藏、搜索、筛选
- 设置：数据、隐私、默认样式

等功能变多后再考虑底部 Tab：

- 首页
- 扫码
- 记录
- 设置

## 5. 技术实现建议

### 5.1 二维码生成库

当前采用 `qrcode-generator` 在本地生成二维码矩阵，再由 `QrPreview.vue` 用 `view` 网格渲染；图片导出由 `qrExport.ts` 用 canvas 绘制。后续如替换库，需要满足：

- 支持 H5 和 App。
- 支持 canvas 或图片导出。
- 支持纠错等级。
- 维护状态稳定。
- 不强绑定特定 UI 框架。

### 5.2 扫码能力

优先使用 uni-app 原生能力：

- App 端：`uni.scanCode`
- H5 端：按能力降级，必要时先只支持相册识别或提示使用 App
- 小程序端：后续适配平台扫码能力

### 5.3 本地存储

建议封装 `recordStore`，不要在页面里直接散落 `uni.getStorageSync`。

模块职责：

- 查询记录
- 新增记录
- 更新记录
- 删除记录
- 收藏切换
- 导入导出
- 数据迁移

### 5.4 权限与隐私

需要明确提示的权限：

- 相机：扫码。
- 相册读取：识别图片二维码。
- 相册写入：保存二维码图片。

隐私策略：

- 默认不上传二维码内容。
- WiFi 密码、名片信息、扫码记录默认仅保存在本机。
- 导出文件由用户主动触发。
- 隐私政策页面需要持续同步功能变化，免责声明不得替代必要的合规提示。

## 6. 近期执行计划

建议下一轮继续补齐真机验证和结构化详情：

1. Android 基座真机验证保存二维码图片到相册。
2. H5 端保存图片降级为下载或长按预览。
3. 使用另一台设备验证 WiFi 二维码识别。
4. 使用联系人应用验证 vCard 名片导入。
5. 详情页按 WiFi、名片、文本、链接做结构化展示。
6. 增加 JSON 导入、去重和导出文件下载能力。
7. 补充 Android 发布检查清单和真机验证记录。
8. 扩展国际化覆盖到后续新增功能，并评估是否加入更多语言。

## 7. 暂缓事项

以下功能先不进入 MVP：

- 用户账号
- 云同步
- 会员付费
- 在线短链接
- AI 解析二维码内容
- 批量 CSV 生成
- 复杂美化模板市场

原因：这些功能会引入后端、合规或复杂交互，容易拖慢首版可用工具箱落地。
